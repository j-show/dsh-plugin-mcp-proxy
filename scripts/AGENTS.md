# Build scripts

- Build only this repository and declared npm dependencies. No consumer paths or workspace fallback.
- Keep intermediates under .artifacts and delivery files under release. Validate dependency closure before publishing an EXE or plugin archive.
- Development uses public DSH CLI/profile APIs and checkout-owned state. Keep initialization idempotent, refuse unowned or linked state paths, and test trust/proxy behavior without changing certificate stores. CI evidence must name the source revision and actual command exits; do not upload development state.
- Portable NSIS packaging uses an owned temporary short-path drive alias. Never replace an existing mapping; remove only a mapping whose target still matches this build directory, including on failure.
- Native product acceptance must read the successful build receipt, verify EXE and runtime hashes/inventory, refuse occupied service slots and require all five cases with zero skips. Never choose artifacts by directory timestamps, stop unknown owners, or upload private product-test state.
- Browser E2E uses real headed Chrome/Edge and ownership-fenced UIA/Win32 actions. Require WTS active state, matching input/process desktops and an unoccupied URI owner. Remove only newly imported CA fingerprints and this run's registrations/processes; never upload profiles, private keys or bootstrap tokens.
- Certificate warnings may be confirmed only in the captured test helper process/creation identity with its expected image and test CA text. Use native control patterns or verified pointer hit targets; never click an arbitrary Yes button or an occluding window.
- MCP startup markers may include exited version-negotiation children. Track only creation-fenced live descendants of the owned service; reject live unowned markers and compare stable live identities across second launch.
- Fresh DSH onboarding must be handled through its real nonbinding Continue and Configure later controls. Verify pointer hit targets before browser clicks so a modal cannot redirect a background action.
- Protocol consent uses one real keyboard input after the exact button's focus, owning foreground window and bounds remain stable through Chromium's input-protection interval. Require prompt dismissal and handler execution; never select a window by enumeration order, send blind keys, inject consent callbacks or disable protection.
- Retry only confirmed pre-input failures and preserve the last native reason. Partial input must attempt key release and fail without replay; timeout, missing diagnostics and any post-dispatch failure are uncertain.
- UIA FromPoint may return a logical ancestor. Only an identified notification icon may accept that case: require an exact physical Win32 root match, ancestry bounded by the whitelisted Explorer root and no overlapping operable peer. Recheck identity, geometry and physical cursor before dispatch; same PID alone is insufficient.
- Browser matrices must prove the notification occlusion guard rejects a test-owned topmost blocker before the real tray click. Always destroy that blocker, never inject Electron tray events, and stop on uncertain mouse input after attempting button release.
- Uncertain native input also disables later tray UI cleanup. Use the existing configuration/creation-fenced service stop and private process teardown instead; cleanup must not replay a right-click whose result is unknown.
- Routing diagnostics contain only fixed activation stages, whitelisted query-free paths and status codes; native hit diagnostics use PID/type/class, never Name/Title. Do not publish raw URI, headers or server output.
- Protocol screenshots require page token checks, verified process/root ownership and the consent subtree (Open/Cancel/checkbox). Scan Name/Value for secrets, refuse a full browser root, and verify the crop excludes the Omnibox/address bar.
- Resolve modern notification overflow by its unique SystemTray.OverflowButton ID before localized legacy labels. Tray diagnostics contain only control types, safe IDs and fixed role labels; never raw tooltips.
- Tray roots/popups must belong to the verified Shell_TrayWnd process; include owned XAML overflow popups without scanning other applications' popup windows.
- Generic XAML popups require a known notification-icon ID in addition to the exact app label; ambiguous icons or missing shell surfaces must not count as successful absence.
- After exit, inspect hidden notification overflow as well as visible icons; close only a popup opened by that verification. Expand once and wait for the surface instead of repeatedly toggling it.
- Notification tooltip text may be HelpText rather than Name. Match the exact app label in either property, retain native control/root checks, and report only fixed text categories.
- URI preflight reads merged ClassesRoot so a machine-wide handler cannot be shadowed by a test's user registration.
- Query process images through limited-access kernel handles; MainModule can be absent during startup. The suspended-process regression must terminate/wait its own child by the captured creation handle and close every handle before reporting.
- Deduplicate matching controls by UIA identity before requiring uniqueness across owned top-level windows. A modal control can appear through its own and its owner's trees; distinct same-name controls must still be rejected.
- GUI confirmations share the pre-input-only retry policy and preserve the last native refusal. Treat exceptions after UIA Invoke as uncertain too; certificate polling stops after a successful or uncertain invoke and only awaits the original certificate operation.
